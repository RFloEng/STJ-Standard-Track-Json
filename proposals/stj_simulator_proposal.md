# Proposals from the simulator team (Project Chrono)

Eleven items found by running a vehicle simulator on STJ tracks (T1 to T9 checked against commit `503f0f8`; T10 and T11 added by the team on 2026-11-12). What was done, item by item.

| # | Item | Outcome |
|---|---|---|
| T1 | Tyre class and reference surface | **Done** (2026-11-27). The defaults are stated (§6.2): no `reference.surface` means STJ-REF (division by 1), no `tyre_class` means the generic values. The class list lives in STJ (`schema/tyre-classes.schema.json`, the names unchanged), with a copy in SVJ. `reference.surface` is `"STJ-REF"`, the surface written out, or a pointer `{uri, surface}` into an STJ file. SVJ v0.113 has both fields. |
| T2 | Which prims are the collision surface | **Done** (§7.2): the only role `collision` means every Mesh prim; with other roles, prims marked `stj:collision = true` (on the prim or an ancestor). `stj_core.usd_collision_meshes`; the validator warns when a multi-role file marks none. |
| T3 | Merge or replace, and step 3 | **Merge: done** (§6.3, field by field, class wins). **Step 3 kept:** the division by the tyre's reference surface applies to class-specific values too, because a class value is relative to STJ-REF and the tyre's fit was made on its reference surface; skipping it counts the surface twice. A worked example is in §6.4. |
| T4 | Wet grip rules | **Done** (§6.4, §6.8): `mu.sliding` scales the sliding μ of models that have one, informative for MF; `wet_gain` is one number for both axes and 0 when absent; marbles use the session `level` only; line states apply per palette entry; `wet_response(0) = 1`, applied where d > 0. |
| T5 | Blending of non-scalar fields | **Done** (§6.3): numbers by weight, curves evaluated per entry then blended, categorical fields from the largest weight, absent fields take their default. |
| T6 | Surface precedence and conditional maps | **Done** (§6.3): the binding wins over the material name; `surfaces.maps[]` governs the contact and `ground.materials[]` the look; the first map whose condition holds, else level 1; `when` against the §11.1 defaults when no signal is set. |
| T7 | Definition of `t` near corners | **Done** (§4): the nearest point of the reference line, ties to the smaller `s`; `project(x, y, near, window)` for a continuous, cheap search. Tests in `tests/test_validate.py` (`SimulatorProposals`). |
| T8 | Small fixes | **Done:** `texCoord2f` accepted (both were read already; §7.7), `spread` guard in `line_state_value`, ray tolerance note (§7.4). **Done** (2026-11-27): `stj_core.FilmQuery` takes a point and a surface or a blend, with one film depth for the blend (§6.3); the validator is `tools/stj_validate.py`, and `tools/validate.py` stays as an alias so that documented commands keep working. A program imports `stj_validate`; `validate(path)` returns the findings. |
| T9 | Examples for unexercised features | **Done** (2026-11-27): `examples/features/` with `expected_queries.json`, worked out by hand; `tools/stj_query.py` is the reference. It made the spec state how weights are sampled, where an OpenCRG patch in mode `attached` is read and how a Y-up stage is turned. The OpenCRG file follows the form of the ASAM sample files and has not been opened with the ASAM library. |
| T10 | Merge depth of `deformable`; absent `applies_to`; a test vector | **Done** (2026-11-27), as the team read it: `deformable.effective` merges key by key and `terramechanics` is replaced; a line state without `applies_to` lies on every surface. §6.4 works out a blended contact with a line state. §6.4 step 2 now says "merge", the leftover the team noted. |
| T11 | An example with a visual layer | **Done** (2026-11-27): `examples/features/visual_layer.usda`. Kerb paint is a texture on the kerb's material; no new field (§7.2). |
